> 以下 Mermaid 流程图展示各核心业务场景中，控制层（Controller/AOP/定时任务）到服务层的完整触发路径与数据流向。

## 用户注册与登录触发路径

> 三条认证路径（密码登录 / 验证码登录 / 微信OAuth）汇聚到 JWT 双 Token 生成与 STOMP 连接

```mermaid
flowchart TD
    subgraph ENTRY["入口"]
        CTL_USER["UserController"]
    end

    subgraph METHODS["端点方法"]
        SEND_CODE["sendCode()<br/>POST /user/send"]
        REGISTER["register()<br/>POST /user/register"]
        LOGIN["login()<br/>POST /user/login<br/>loginType=1 密码 / =2 验证码"]
        WECHAT_LOGIN["wechatLogin()<br/>POST /user/wechat/login"]
        REFRESH["refreshToken()<br/>POST /user/refresh"]
    end

    CTL_USER --> SEND_CODE
    CTL_USER --> REGISTER
    CTL_USER --> LOGIN
    CTL_USER --> WECHAT_LOGIN
    CTL_USER --> REFRESH

    subgraph SVC["UserServiceImpl"]
        SV_SEND["sendCode(phone,operation)<br/>→ Redis 存验证码 · TTL 300s<br/>→ 阿里云 SMS 发送"]
        SV_REG["register(RegisterDTO)<br/>→ 验证码校验 · 密码 BCrypt<br/>→ insert User · 生成双 Token"]
        SV_LOGIN["login(LoginDTO)<br/>→ loginType=1: BCrypt 校验<br/>→ loginType=2: Redis 验证码校验<br/>→ Redis 失败计数(5次/300s)<br/>→ 生成双 Token"]
        SV_REFRESH["refreshToken(refreshToken)<br/>→ 校验 refresh JWT 签名<br/>→ 重新生成双 Token"]
    end

    SEND_CODE --> SV_SEND
    REGISTER --> SV_REG
    LOGIN --> SV_LOGIN
    WECHAT_LOGIN -->|"OAuth → openid<br/>首次自动注册"| SV_LOGIN
    REFRESH --> SV_REFRESH

    subgraph OUTPUT["输出"]
        JWT["JwtUtil.createJWT()<br/>access_token (2h)<br/>refresh_token (7d)"]
        STOMP_CONN["STOMP WebSocket 连接<br/>登录成功自动连接"]
    end

    SV_REG --> JWT --> STOMP_CONN
    SV_LOGIN --> JWT --> STOMP_CONN
    SV_REFRESH --> JWT

    style ENTRY fill:#FFF0ED,stroke:#FF6B4A,stroke-width:2px
    style SVC fill:#D4F5F0,stroke:#2EC4B6,stroke-width:2px
    style OUTPUT fill:#EEF2FB,stroke:#5B9BD5,stroke-width:2px
```

**关键路径说明**：
- **密码登录**：login() → Redis 失败计数检查 → BCrypt 校验 → 双 Token 生成 → STOMP 连接
- **验证码登录**：phoneLogin() → Redis 验证码校验(读后即删) → 双 Token 生成
- **微信登录**：wechatLogin() → wx.login code → 后端换取 openid → 首次自动注册 → 双 Token 生成
- **注册**：register() → 验证码校验 → BCrypt 加密 → insert User → 双 Token 生成 → STOMP 连接

## 任务发布触发路径

> TaskController.publish → TaskServiceImpl → PaymentServiceImpl 的完整事务链

```mermaid
flowchart TD
    subgraph CTL["TaskController (user)"]
        PUBLISH["publish(TaskPublishDTO)<br/>POST /task/publish"]
    end

    PUBLISH --> GUARD{"前置校验"}
    GUARD -->|"BaseContext<br/>getCurrentUserId()"| CERT{"isCertify >= 2?"}
    CERT -->|"否"| REJECT["BusinessException<br/>'请先完成实名认证'"]
    CERT -->|"是"| PAY_PWD["verifyPayPassword<br/>支付密码校验"]

    PAY_PWD --> PARAM["@Valid 参数校验<br/>reward · expireMinutes<br/>pickupAddress 非空"]

    PARAM --> SAVE["TaskServiceImpl.createTask()<br/>→ 生成 taskNo 编号<br/>→ INSERT task (status=1)<br/>→ INSERT task_image (如有)"]

    SAVE --> PAY["PaymentServiceImpl<br/>.payForTask(userId, taskId, reward)"]

    subgraph PAY_FLOW["资金冻结流程"]
        direction LR
        P1["SELECT ... FOR UPDATE<br/>行锁查询 User"]
        P2["校验 balance >= amount"]
        P3["UPDATE user<br/>SET balance = balance - amount"]
        P4["INSERT payment_idempotent<br/>key: PAY:task:{taskId}"]
        P5["INSERT transaction_record<br/>type=1 (任务支出)"]
        P1 --> P2 --> P3 --> P4 --> P5
    end

    PAY --> PAY_FLOW

    PAY_FLOW --> CACHE["@CacheEvict<br/>task_hall:* · task_detail:*"]

    style CTL fill:#FFF0ED,stroke:#FF6B4A,stroke-width:2px
    style PAY_FLOW fill:#FEF3C7,stroke:#F59E0B,stroke-width:2px
    style SAVE fill:#D4F5F0,stroke:#2EC4B6,stroke-width:2px
    style REJECT fill:#FEE2E2,stroke:#EF4444
```

**关键路径说明**：
- `payForTask()` 在 `createTask()` 写库**之后**执行——先创建任务记录，再冻结资金
- `payForTask()` 使用 `SELECT FOR UPDATE` 行锁防止并发超扣，`payment_idempotent` 唯一约束防止重复扣款
- 发布成功后通过 `@CacheEvict` 清除任务大厅和详情缓存，保证数据实时性

```mermaid
        SV_CANCEL["cancelOrder(orderId, reason)<br/>→ 状态机校验取消合法性<br/>→ UPDATE status=5 · cancel_reason<br/>→ (退款/信用分由 task 级取消触发)"]
    end

    M1 --> SV_ACCEPT

    M3 --> SV_DELIVER

    subgraph CROSS["跨切面联动"]
        REDISSON_LOCK["Redisson RLock<br/>等待3s · 持有10s"]
        STATE_MACHINE["OrderStateMachine<br/>validate(current→target)"]
        PAYMENT["PaymentService<br/>payToRunner / refundForTask"]
        CREDIT["CreditScoreAspect<br/>@AfterReturning 信用分变更"]
    end

    SV_ACCEPT --> REDISSON_LOCK

```

**关键路径说明**：
- **接单**：Redisson 分布式锁（`WAIT:task:{taskId}`）确保并发下仅一人接单成功；`TaskStateMachine` 校验任务 1→2
- **状态流转**：`confirmPickup`/`confirmDeliver`/`confirmComplete` 使用 `OrderStateMachine` 校验订单级状态转移
- **完成结算**：`confirmComplete` 触发 6 步链——双状态机校验 → `payToRunner()` → `CreditScoreAspect` → `@CacheEvict dashboard`
- **取消退款**：退款和信用分扣减由 **task 级取消**（`TaskServiceImpl.cancelTask()`）触发，order 级 `cancelOrder()` 仅更新订单状态
- **定时兜底**：`OrderAutoCompleteChecker` 每 60s 扫描超时订单自动确认

## 信用分系统触发路径

> CreditScoreAspect（AOP 切面）+ ReviewController（评价）+ AuditController（管理员）三种触发路径

```mermaid
flowchart TD
    subgraph TRIGGER["三种触发入口"]
        direction LR
        TG1["CreditScoreAspect<br/>@AfterReturning 切面<br/>拦截 confirmComplete 完成结算"]
        TG2["ReviewController<br/>(用户评价)<br/>create()"]
        TG3["AdminRunnerController<br/>(管理员封禁/解封)<br/>toggleBan()"]
    end

    subgraph SVC["processCreditOnComplete 阶梯计分"]
        SV_CHANGE["processCreditOnComplete(orderId)<br/>→ 计算时间差 准时/提前/延迟<br/>→ 提前送达: +5 · 准时: +1<br/>→ 延迟0-30min: -2 · 30-60min: -5<br/>→ 延迟60min+: -10<br/>→ 冻结阈值: credit_score < 50 → ban 3天"]
    end

    subgraph REVIEW["评价触发"]
        R1["create(ReviewCreateDTO)<br/>→ rating >= 4 (好评): +2<br/>→ rating == 1 (差评): -5"]
    end

    TG1 -->|"完成订单自动计算"| SV_CHANGE
    TG2 --> R1
    TG3 -->|"封禁/解封跑腿员"| SV_CHANGE

    SV_CHANGE --> LOG["credit_log 审计表<br/>runnerId · delta · scoreBefore<br/>scoreAfter · reasonType<br/>relatedOrderId · createdAt"]
    LOG --> CACHE["@CacheEvict<br/>runner:leaderboard:*"]

    subgraph BAN["自动冻结/解冻"]
        BAN1["credit_score < CREDIT_FREEZE_THRESHOLD<br/>→ is_banned=1<br/>→ ban_until=NOW()+3天"]
        BAN2["CreditRecoveryTask<br/>@Scheduled 5min<br/>→ ban_until < NOW()<br/>→ is_banned=0, 恢复至阈值"]
    end

    SV_CHANGE --> BAN1
    BAN2 --> BAN1

    style BAN fill:#FEF3C7,stroke:#F59E0B,stroke-width:2px
    style REVIEW fill:#EDE9FE,stroke:#8B5CF6,stroke-width:2px

    style TRIGGER fill:#FFF0ED,stroke:#FF6B4A,stroke-width:2px
    style SVC fill:#D4F5F0,stroke:#2EC4B6,stroke-width:2px
    style BAN fill:#FEF3C7,stroke:#F59E0B,stroke-width:2px
```

**关键路径说明**：
- **AOP 切面自动触发**：`@AfterReturning` 仅拦截 `confirmComplete`，在订单完成后自动计算本单信用分变更
- **阶梯计分**：根据送达时间差——提前 +5、准时 +1、延迟 0-30min -2、30-60min -5、60min+ -10
- **评价联动**：用户评价后——好评(rating>=4) +2、差评(rating==1) -5
- **管理员封禁**：超管可通过 `toggleBan()` 封禁/解封跑腿员，不能直接调整信用分
- **自动冻结**：信用分低于阈值自动封禁 3 天；`CreditRecoveryTask` 每 5 分钟扫描解封
- **完整审计**：每次变更写入 `credit_log` 表

## 支付与资金托管触发路径

> UserTransactionController + TaskController + OrderController → PaymentServiceImpl 的三路资金流

```mermaid
flowchart TD
    subgraph ENTRY["触发入口"]
        direction LR
        E1["UserTransactionController<br/>recharge() · withdraw()"]
        E2["TaskController<br/>publish()"]
        E3["TaskOrderServiceImpl<br/>confirmComplete()"]
        E4["TaskServiceImpl<br/>cancelTask()"]
        E5["定时任务<br/>TaskTimeoutChecker"]
    end

    subgraph SVC["PaymentServiceImpl"]
        direction TB
        P1["recharge(userId, amount, payPassword)<br/>→ 验证支付密码<br/>→ SELECT FOR UPDATE 查余额<br/>→ UPDATE balance + amount<br/>→ INSERT transaction_record (type=3)<br/>→ INSERT payment_idempotent"]
        P2["withdraw(userId, amount, payPassword)<br/>→ 验证支付密码<br/>→ 校验 amount >= 10 (最低提现)<br/>→ SELECT FOR UPDATE 查余额<br/>→ UPDATE balance - amount<br/>→ INSERT transaction_record (type=4)"]
        P3["payForTask(userId, taskId, amount)<br/>→ SELECT FOR UPDATE<br/>→ UPDATE balance - amount<br/>→ INSERT payment_idempotent<br/>→ INSERT transaction_record (type=1)"]
        P4["payToRunner(runnerId, taskId, amount)<br/>→ SELECT FOR UPDATE<br/>→ UPDATE balance + amount<br/>→ INSERT payment_idempotent<br/>→ INSERT transaction_record (type=2)"]
        P5["refundForTask(userId, taskId, amount)<br/>→ SELECT FOR UPDATE<br/>→ UPDATE balance + amount<br/>→ INSERT payment_idempotent<br/>→ INSERT transaction_record (type=5)"]
    end

    E1 --> P1
    E1 --> P2
    E2 --> P3
    E3 --> P4
    E4 --> P5
    E5 --> P5

    subgraph SAFEGUARD["资金安全机制"]
        LOCK["SELECT FOR UPDATE<br/>行级悲观锁"]
        IDEM["payment_idempotent<br/>数据库唯一约束<br/>幂等键: PAY/REFUND/task:{id}"]
        AUDIT["transaction_record<br/>balanceBefore<br/>balanceAfter<br/>完整审计追踪"]
    end

    P1 --> LOCK
    P2 --> LOCK
    P3 --> LOCK
    P4 --> LOCK
    P5 --> LOCK
    P1 --> IDEM
    P3 --> IDEM
    P4 --> IDEM
    P5 --> IDEM
    P1 --> AUDIT
    P2 --> AUDIT

    P4 --> AUDIT

    style ENTRY fill:#FFF0ED,stroke:#FF6B4A,stroke-width:2px
    style SVC fill:#D4F5F0,stroke:#2EC4B6,stroke-width:2px
    style SAFEGUARD fill:#FEE2E2,stroke:#EF4444,stroke-width:2px
```

**资金流转路径说明**：
- **充值/提现**（用户主动）：验证支付密码 → SELECT FOR UPDATE → 余额变更 → 写入流水
- **任务支出**（发布时冻结）：payForTask → 余额扣减为冻结态 → 幂等记录防重
- **跑腿收入**（完成时结算）：payToRunner → 金额从快照转出 → 微信通知（预留）
- **取消退款**（任务/订单取消）：refundForTask → 全额退回发布者 → 信用分联动扣减
